# 다음 개선안 — 틈새 학습 구조 (상의용 초안)

기준: 2026-10-16. 사용자와 정리한 제품 방향 초안이다. **V2(PLAN_V2)에서 채택해 구현했다.** 아래 '확인이 필요한 실험'의 결과는 VERIFICATION을 본다. 기능 결함 메모는 [UI_AUDIT](UI_AUDIT.md)에 따로 있다.

## 모토

> 공부하는 앱이 아니라, **공부한다고 착각하는 앱.**
> 그런데 막상 각 잡고 공부할 때 "아, 이게 도움이 됐구나"를 느끼게 하는 앱.

지식 퍼즐을 맞추는 구조다. 주변 지식 조각이 많이 쌓이면 본격적인 공부에서 빈칸이 쉽게 메워진다.

## 두 층 구조

| | 틈새 층 (메인 기믹) | 앱 층 |
| --- | --- | --- |
| 장소 | 앱 밖. 잠금 화면, 폰을 잠깐 보는 순간, 앱 전환 순간 | 사용자가 앱을 직접 열었을 때 |
| 난이도 | 아주 쉬움. 보고 바로 넘겨도 방해가 되지 않는 수준 | 한 단계 깊은 개념과 제대로 된 문제 풀이. 무겁지는 않게 |
| 길이 | 1~2초 안에 읽히고, 답하거나 넘기는 데 한 번이면 끝남 | 마음먹고 하는 짧은 학습 세션 |
| 목적 | 반복 노출로 되새기기, 조각 수집 | 조각을 엮어 이해하기, 실력 확인 |
| 기록 | **학습 기록과 복습 일정에 반영** | 학습 기록과 복습 일정에 반영 |

현재 구현은 반대로 되어 있다. 앱 안이 30~90초짜리 가벼운 층이고, 틈새(알림)는 학습하러 오라는 호출에 그친다.

### 두 층의 연결이 핵심

"도움이 됐구나"는 저절로 느껴지지 않으므로 설계로 드러내야 한다. 아이디어 수준이며 검토가 필요하다.

- 앱 층의 심화 개념 안에서, 틈새에서 이미 만난 조각을 표시한다. 예: "이 중 3개는 이미 알고 있어요"
- 심화 문제의 보기나 해설이 틈새 조각을 근거로 쓴다
- 기록 화면을 "푼 문제 수"가 아니라 "맞춰진 퍼즐 조각" 관점으로 보여 준다

## 틈새 표면 후보 (Android)

조사 수준이며, 실기기 확인 전에는 가능하다고 확정하지 않는다.

| 후보 | 가능성 | 상호작용 | 주의점 | 확인 상태 |
| --- | --- | --- | --- | --- |
| 조용한 상주 카드 알림 | 높음. 표준 API. 소리·진동 없는 알림을 잠금 화면에 계속 두고 문제를 교체 | 보기 버튼으로 응답. 응답하거나 일정 시간이 지나면 다음 카드로 교체 | 저중요도(silent) 채널은 '잠금 화면에서 조용한 알림 숨김' 설정에 가려질 수 있다(Pixel 기본값이라는 개발자 보고가 있으나 공식 확인은 못 함). 기본 중요도 채널에 소리·진동만 끄는 방식을 검토. 잠금 해제마다 즉시 교체는 앱 프로세스가 없으면 어렵고, 주기 교체(WorkManager 최소 15분) 또는 응답 시 교체가 현실적. 사용자가 밀어서 지울 수 있음 | 미검증 |
| 잠금 화면 알림 + 응답 버튼 | 높음. 표준 API | O/X·보기 버튼으로 잠금 해제 없이 응답 가능(액션을 BroadcastReceiver로 처리) | 사용자의 잠금 화면 알림 표시 설정, 민감 내용 숨김(public version), 알림 피로, 절전 시 지연 | 미검증 |
| 홈 화면 위젯 | 높음. 표준 API(Glance) | 위젯 안에서 탭으로 응답 가능 | 사용자가 직접 배치해야 함. 갱신 주기 제한 | 미검증 |
| 잠금 화면 위젯 | 중간. Android 16 QPR2부터 휴대폰 잠금 화면 위젯 페이지가 생겼다는 보도. 제조사(삼성 One UI 등) 채택 여부는 확인 못 함 | 위젯과 동일 | 기기·OS 버전에 따라 지원이 갈림. 기본 잠금 화면이 아니라 별도 페이지 | 미검증 |
| 잠금 화면 배경화면 | 중간. `WallpaperManager` `FLAG_LOCK`과 `SET_WALLPAPER` 권한 | 보기 전용. 응답 불가 | 사용자 배경화면을 덮어씀. 노출 기록을 학습 기록으로 보기 어려움 | 미검증 |
| 앱 전환 순간 팝업 | 낮음, 위험 높음 | 오버레이로 문제 표시 | 앞에 있는 앱을 감지하려면 접근성 서비스나 사용 기록 접근 권한이 필요하다. Play 접근성 정책 신고와 고지 의무가 있고, Android 17 고급 보호 모드에서는 접근성 도구가 아닌 앱의 접근이 차단된다는 보도가 있다. 오버레이 정책과 배터리 문제도 있다 | 미검증, 신중 |

현실적인 1차 조합은 **조용한 상주 카드 알림 + 홈 위젯**이다. 울리는 알림으로 보채지 않고, 잠금 화면을 켤 때 이미 카드가 놓여 있게 한다. 잠금 화면 위젯은 지원 기기에서 추가 표면으로 둔다. 앱 전환 팝업은 정책 확인 전에는 구현하지 않는다.

### 알림 하나에 기능을 넣을 수 있는 범위

상주 카드를 커스텀 알림 레이아웃(RemoteViews)으로 만들면, 알림 하나 안에서 문제 → 응답 → 결과 → 다음 카드까지 끝낼 수 있다. 다만 크기와 구성 요소에 제한이 있다.

- 높이: 공식 문서상 버전에 따라 **접힌 상태는 48dp, 펼친 상태는 252dp까지만 보장**된다. 이보다 크게 만들면 잘릴 수 있다.
- 형태: Android 12(API 31) 이상을 대상으로 하면 완전한 커스텀 알림은 만들 수 없다. 시스템이 앱 아이콘·이름 헤더가 있는 표준 틀을 씌우고, 그 안의 내용 영역만 꾸밀 수 있다.
- 펼침: 잠금 화면과 알림창에서는 보통 **접힌 상태로 표시**된다. 펼치려면 사용자가 아래로 끌어야 한다. 그래서 접힌 48dp만으로도 핵심 행동(한 줄 문제 + O/X)이 끝나야 한다.
- 상호작용: 버튼 탭(PendingIntent)은 가능하다. 스크롤, 애니메이션, 자유 입력은 사실상 불가능하다. 라디오 버튼 같은 선택 컨트롤 지원 여부는 RemoteViews 레퍼런스로 확인이 필요하다.

설계 초안: 접힌 상태 = 한 줄 문제 + O/X 버튼, 펼친 상태 = 보기 3~4개 + 정답·한 줄 해설 + '다음'과 '앱에서 깊게' 버튼.

### 확인이 필요한 실험

1. API36 에뮬레이터와 실기기 1대에서 잠금 상태 알림의 보기 버튼 응답 → SQLite 기록 → 알림 갱신까지 확인. 커스텀 레이아웃의 접힘/펼침 표시, 삼성 One UI에서의 렌더링 차이 포함
2. Expo 프로젝트에서 Android 위젯을 config plugin으로 넣는 방법 확인(SDK57 문서 기준)
3. Android 16 QPR2 이상 기기에서 잠금 화면 위젯 표시 여부
4. 앱 전환 팝업: Play 접근성·오버레이 정책 원문 확인 후 진행 여부 결정

## 참고: 듀오링고

- 푸시 알림: 여러 문구 중 무엇을 보낼지 bandit 알고리즘으로 고르고, 같은 문구가 반복되지 않게 최근 노출 문구의 가중치를 낮춘다(2차 자료 기준).
- 위젯: 홈 위젯은 스트릭과 마스코트가 시간대·스트릭에 따라 표정이 바뀐다. iOS 잠금 화면 위젯은 이미지 없이 스트릭 숫자만 보여 준다.
- 차이: 듀오링고의 틈새 표면은 **"돌아와서 공부해"라는 호출**이다. 틈지식은 틈새 표면에서 **학습 자체가 끝나야** 한다. 보채기는 따라 하지 않고, 위젯처럼 사용자가 고른 상주 표면이라는 점만 참고한다.

## 디자인 방향에 주는 영향

- 두 층이 서로 다른 시각 언어를 쓴다. 틈새는 장식 없이 큰 글자와 한 번의 행동, 앱은 밀도와 깊이가 있는 학습 공간이다.
- '틈'이라는 이름과 '퍼즐 조각' 개념을 시각 언어의 출발점으로 삼는다. 현재 화면에는 콘셉트가 드러나지 않는다.
- 앱 화면 시안은 [디자인 캔버스](https://claude.ai/artifact/QB6oXbF15ekWToBdQoffXx)의 **D안(틈 + 조각)**으로 방향을 잡았다(사용자 선호, 2026-10-16). 어두운 바탕(`#121513`)에는 부가 정보(퍼즐 지도, 진행, 설정 버튼)만 두고, 기울어진 연한 민트 띠(`#E8F0EA`) 안에 핵심(문제, 보기, 정답)을 둔다. 선택 상태는 검정 바탕 + 민트 글씨로 뒤집는다. 로고는 쓰지 않는다. 설정에 들어가면 띠가 벌어져 화면 전체가 밝아진다.

### 표면별 시각 정체성

| 표면 | 정체성 강도 | 방식 |
| --- | --- | --- |
| 잠금 화면 상주 카드 | 최소 | 시스템 알림 모양을 따른다. 잠금 화면은 사용자의 공간이고, Android 12+는 시스템 틀을 강제하며, 알림창 색은 라이트·다크 모드와 기기 테마를 따른다. 우리 색을 강하게 넣으면 광고처럼 보이고 다크 모드·One UI에서 대비가 깨지기 쉽다. 정체성은 말투와 구조(문제 자체가 놓여 있음, 짧은 질문 한 줄, 답 버튼)로 내고, 색은 시스템이 허용하는 강조색에만 민트를 쓴다 |
| 홈 위젯 | 중간 | 사용자가 직접 배치하는 자리이므로 작은 민트 띠 카드처럼 앱 언어를 조금 더 보여 줄 수 있다 |
| 앱 | 완전 | 어두운 바탕 + 틈(밝은 띠) 언어 전체 |

잠금 화면에서는 조용하다가, 카드를 탭해 앱에 들어올 때 비로소 어두운 화면과 틈이 나타난다. 이 대비 자체를 경험으로 삼는다.

## Astra와 상의할 질문

1. 틈새 1차 표면을 알림 응답 + 홈 위젯으로 시작하는 것이 맞는가
2. 틈새 응답을 앱 층 채점과 같은 무게로 복습 일정에 반영할지, 가중치를 다르게 둘지
3. 마이크로 카드와 심화 문제의 콘텐츠 작성·검수 범위와 일정
4. 알림 빈도의 기본값과 '방해되지 않음'을 확인하는 기준
5. 현재 MVP 검수(FIX.C1·C2 재검수)와 이 개편의 순서
