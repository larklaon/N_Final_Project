# V4 아이디어 정리

2026-10-18. 사용자와 나눈 V4 방향 초안이다. 아직 구현 계획이 아니다. 출발점은 "AI 기능이 모자라다"는 사용자 의견이다.

## 이 앱에서 중요한 것 (기존 문서)

[NEXT_DIRECTION](NEXT_DIRECTION.md)과 [PRODUCT](../PRODUCT.md)에 이미 적혀 있다.

1. **틈새가 메인 기믹이다.** 잠금 화면·위젯에서 1~2초 만에 스치고, 학습이 거기서 끝난다. "돌아와서 공부해"라는 호출이 아니다.
2. **두 층의 연결이 핵심이다.** "'도움이 됐구나'는 저절로 느껴지지 않으므로 설계로 드러내야 한다." 모토의 뒷부분("막상 각 잡고 공부할 때 '아, 이게 도움이 됐구나'를 느끼게 하는 앱")이 이것이다.

여기에 V3에서 정한 원칙이 더해진다. 우리 서버 없이 앱과 사용자의 ChatGPT(SIWC)만 쓰고, AI 없이도 둘러보기로 동작하며, 화면에 설명 문장을 늘어놓지 않는다.

## 지금 AI가 모자란 이유

V3의 AI는 **앱 안쪽에만** 있고, 위의 두 핵심(틈새와 연결)에는 닿지 않는다.

| 기능 | 지금 | 빈 곳 |
| --- | --- | --- |
| 7일 계획 | 앱 문제의 출제 순서만 정한다. 이유 문장을 지운 뒤로는 화면에 안 보인다 | 잠금 화면·위젯 덱은 복습 일정 순서로만 만들어지고 계획을 따르지 않는다 |
| 계획 입력 | 지식별 해상도·반감기·마지막으로 다룬 날, 최근 14일 정답 수, 지난 계획 달성도 | 대화 내용, 어떤 보기를 골라 틀렸는지가 들어가지 않는다. V3 아이디어의 "대화도 메모리에 남아 다음 계획에 반영된다"가 빠져 있다 |
| 물어보기 | 힌트·왜 그런지, 본문 인용, 개념별 기록 | 앱 안에서 끝나고, 대화에서 드러난 헷갈림이 다른 곳으로 이어지지 않는다 |
| 콘텐츠 | 미리 쓴 묶음(정보처리기사 기초 60, SQLD 12)과 개념 정의로 만든 용어 문제 | 반복하면 답을 외우게 되고, 내 약점에 맞춘 문제가 없다 |

## 제안

### 1. 내가 헷갈린 걸로 AI가 틈새 카드를 만든다 — 1순위

- 앱 문제에서 틀린 보기, 채팅에서 물어본 것, 다시 풀기에서 또 틀린 것을 재료로 AI가 잠금 화면용 O/X 카드를 만든다.
- 만든 카드는 그 개념에 묶여 다음 덱에 섞인다. 예: 스택·큐를 헷갈렸다면 다음 날 잠금 화면에 "큐는 먼저 들어온 걸 먼저 꺼낸다"가 스친다.
- 노리는 순간: "어제 물어본 그게 잠금 화면에 있네." 틈새가 일반 문제집이 아니라 **나만의 덱**이 된다.
- 안전장치
  - 형식: 접힌 카드 두 줄(`fitsLockCard`), O/X 하나, 원래 개념 id
  - 정답: 같은 요청 안에서 근거 한 줄을 받고, 별도 요청으로 참·거짓을 다시 확인해 엇갈리면 버린다
  - 양: 하루 몇 장으로 제한하고, 덱 안에서 기존 카드와 섞어 표시는 다르게 하지 않는다
- 기록: 생성 카드의 답도 해상도에 반영한다. 가중치는 기존 틈새 O/X와 같게 시작한다.

### 2. 대화와 오답이 쌓이는 "헷갈림 메모리" — 1번의 기반

- AI가 대화와 오답을 개념별 짧은 메모로 요약해 앱에 저장한다. 예: "스택·큐 꺼내는 순서 혼동", "LEFT JOIN이 왼쪽 행을 버린다고 착각".
- 이 메모가 7일 계획 요청과 1번 카드 생성의 입력이 된다. 계획은 "흐려진 조각"뿐 아니라 "헷갈리는 짝"을 보고 정한다.
- 화면에는 거의 드러나지 않는다. 필요하면 개념 화면의 ⓘ 뒤에 "자주 헷갈린 점"으로만 둔다.
- 앱이 직접 보관하는 자체 메모리다. ChatGPT의 기존 대화·메모리는 가져오지 않는다.

### 3. 연결을 그림으로 보여 주기

- AI가 내 기록과 개념의 `builtOn` 관계를 바탕으로 조각 사이의 연결을 정리한다(큐–스택, 외래키–기본키).
- 퍼즐 화면에서 조각끼리 이어진 모습으로 보여 준다. 앱 문제를 맞히면 이번에 이어진 조각들이 잠깐 반짝인다.
- "도움이 됐구나"를 문장이 아니라 그림으로 드러낸다. 설명 최소 원칙과 맞는다.

### 4. 같은 개념, 새 문제

- 해상도가 오른 조각은 AI가 표현과 상황을 바꾼 변형 문제를 앱 층에 낸다. 정답 위치 외우기를 막고, 해상도가 기억이 아니라 이해를 따라가게 한다.
- 안전장치는 1번과 같다(형식 검사, 정답 재확인). 원래 문제는 그대로 남긴다.

### 5. AI가 만드는 과목 맛보기 — 시연용

- "곧 열려요" 과목이나 사용자가 적은 주제로 AI가 맛보기 묶음(개념 + 틈새 카드 + 앱 문제 + 3단계 설명)을 만든다.
- AI 존재감은 가장 크지만 콘텐츠 품질 위험도 가장 크다. 시연용 맛보기로 한정하고, 기존 콘텐츠 검사(`validate-content`)와 같은 형식 검사를 통과한 것만 설치한다.

## 피할 것

- 채팅 화면을 늘리거나 AI 문장을 화면에 띄우는 것. 앱 밖에서 가볍게 끝난다는 핵심과 설명 최소 원칙에 어긋난다.
- 계획 이유 문장 되살리기. 사용자가 V3에서 군더더기로 지웠다.
- 우리 서버. 지금처럼 앱과 사용자의 ChatGPT만 쓴다.
- AI 없이는 안 되는 기능. 연결이 없으면 기존 콘텐츠와 무작위 출제로 그대로 동작해야 한다.

## 추천 조합

**1 + 2를 V4의 중심**으로 둔다. 2가 재료를 모으고 1이 그것을 틈새로 돌려보낸다. 여유가 있으면 **3**을 얹어 연결을 그림으로 보여 준다. 4와 5는 그다음 후보다.

## 정해야 할 것

- 생성 카드의 하루 개수와 덱 안 비율
- 생성 카드를 화면에서 기존 카드와 구분할지 여부(현재 안: 구분하지 않음)
- 헷갈림 메모리를 언제 갱신할지(대화가 끝날 때마다 / 하루 한 번 계획 요청 때)
- 정답 재확인에 드는 요청 수와 구독 사용량 부담
- 3번 연결 그림의 형태(퍼즐 화면 안의 선 / 별도 지도)
