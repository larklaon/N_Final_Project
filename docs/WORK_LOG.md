# 개발 기록

## 2026-10-16 — V3.W2 — 큰 위젯은 작은 위젯의 문제도 낸다

- 변경: 크기별 문제 종류를 포함 관계로 바꿨다. 큰 위젯은 작은 위젯이 내는 종류를 모두 내고, 카드가 넘어갈 때마다(덱 위치 기준) 돌아가며 고른다.
  - 작게: O/X
  - 기본: 용어 4지선다(2×2) → O/X(큰 O·X 두 개)
  - 크게: 용어 4지선다 → "설명으로 맞는 것은?" 3지선다 → O/X, 선택지는 세로 줄
- 카드에 `variants.choice`(직접 쓴 틈새 3지선다, 섞은 순서)를 추가했다. 선택지가 길어 3지선다는 큰 크기에서만 낸다.
- 검증: Jest 77개·콘텐츠·Gap Kotlin 10개(덱 위치 1개 추가)·debug/androidTest 빌드 통과. API36에서 기본 크기 1번 카드 용어 4지선다 → 2번 카드 O/X, 같은 2번 카드를 크게 늘리면 3지선다로 바뀌는 것을 확인.

## 2026-10-16 — V3.W1 — 위젯 다시 그리기 · 크기별 문제

- 디자인: 홈 위젯을 앱의 D안 언어로 바꿨다. 어두운 카드 위에 기울어진 민트 띠, 띠 안에 세리프 굵은 문제, 아래에 답. 결과도 띠 안에 "맞았어요/정답은 …"과 한 줄 해설, 민트 "다음" 버튼. 런처는 앱에 넣은 글꼴 파일을 쓰지 못해 기기 기본 serif를 쓴다.
- 크기별 문제: Android 12+는 크기별 레이아웃 3벌을 넘겨 런처가 고르고, 그 아래 버전은 크기 변경 신호로 다시 그린다.
  - 작게(1~2줄 높이): 같은 조각의 O/X, 띠 옆 O·X 버튼
  - 기본(4×3): 용어 맞히기 4지선다, 2×2
  - 크게: 같은 4지선다를 세로 4줄, 문제 글자 확대, 해설 넉넉히
- 용어 맞히기: 개념 한 줄 정의의 주어를 "이것은"으로 가려 문제로 쓰고, 같은 과목·영역의 다른 용어 3개를 선택지로 섞는다(`src/domain/term.ts`, 콘텐츠 파일은 그대로). 정의에 답이 섞인 5개는 문장을 따로 썼다. id는 `<개념>~term`, 선택지 id는 개념 id.
- 덱: 카드마다 `variants.ox`·`variants.term`을 함께 보낸다. 잠금 화면 카드는 기존처럼 O/X·객관식을 번갈아 내고, 위젯은 크기에 맞는 모양을 띄운다. 어느 모양으로 답했는지 기록해 결과는 두 화면이 함께 보여 주고, 이벤트는 답한 문제 id로 쌓인다. 앱은 용어 문제를 생성 규칙으로 되살려 기록·해상도에 반영한다(틈새 객관식과 같은 12).
- 수정: 틈새 객관식 정답이 모두 첫 번째 선택지였다. 덱을 만들 때 카드별로 순서를 섞는다.
- 검증: typecheck·lint·Jest 77개(위젯 모양 3개 추가)·콘텐츠 2묶음, Gap Kotlin 9개(위젯 모양 답 1개 추가), debug·androidTest 빌드 통과. API36 홈 화면에서 기본·작게·크게 전환, 정답·오답 결과, 다음 카드, 앱을 연 뒤 위젯 답 2건이 gap_events와 해상도에 반영된 것을 DB로 확인.
- 제한: 다른 런처(삼성 One UI 등)의 크기 판정과 serif 글꼴 모양은 확인하지 않았다.
